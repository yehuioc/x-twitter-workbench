# X 阅读与资料工作台

使用自己的 Chrome 登录 X，保存值得再读的帖子、长文、图片与可核对的引用／同作者回复关系，在本地检索、记笔记、加标签和导出。主动开启 AI 接管后，可以按主题搜索、精读和整理。原文、个人笔记、模型翻译及研究判断分别保存。

当前版本：**0.3.2**。工作台与扩展统一使用这个版本号；版本只在 `extension/manifest.json` 定义，服务、MCP 和下载包直接复用。采用 Chrome 扩展＋本机 Python 服务，不需要导出浏览器 Cookie，也不依赖 X 官方 API。项目不是 X 或 Google 的官方产品。

## 安装与启动

运行需要 **Python 3.10+** 和 **Chrome 116+**；服务只使用 Python 标准库，无需安装第三方 Python 包。自动化测试另需 Node.js 18+。

```shell
git clone https://github.com/yehuioc/x-twitter-workbench.git
cd x-twitter-workbench
python -X utf8 -B run_x.py serve --port 8915
```

如果系统命令叫 `python3`，将上述 `python` 换成 `python3`。Windows 也可以在项目目录双击 `start.cmd`。服务运行后打开 [本地工作台](http://127.0.0.1:8915/)。

1. 在 Chrome 打开 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序”。
2. 选择本项目的 `extension` 目录。工作台“连接与运行”会显示当前安装目录的实际路径，也可下载扩展 ZIP、解压后加载。
3. 在工作台生成十分钟单次配对码，在扩展侧栏输入。
4. 回到已登录的 X 页，点击“绑定我当前看到的 X 页”。绑定使用自己的 Profile 链接与账号切换入口核对 handle，身份不一致就拒绝绑定。
5. 手动保存无需 AI 接管；需要在线研究时，主动开启“允许 AI 操作这个标签页”。

扩展固定连接本机端口 **8915**；更改服务端口主要供隔离测试使用，扩展不会自动发现其他端口。服务只监听 loopback，保留 Host、Origin、配对及页面令牌检查，不应通过公网代理暴露此端口。升级扩展后，在 Chrome 刷新扩展并重新开启接管即可；配对凭据继续有效。

## 保存、阅读与导出

- 帖子底部原生操作栏的文件夹加号用于“保存到本地工作台”。按钮与回复、转帖、点赞处于同一栏；保存成功显示绿色勾，失败保留图标和原因提示。
- 从列表保存时，进入详情、尝试展开长文、核对帖子 ID 与内容稳定，再保存；之后尝试返回原列表和滚动位置。返回失败会说明，已存资料保留。
- 同作者线程只连接有明确回复关系、作者一致且本轮取得的帖子，按父帖到回复排序；引用单独记录，同名或视觉相邻不算线程证据。每轮最多10条，始终保留部分覆盖说明。
- 原文按字符串 ID 去重，正文、媒体或覆盖变化保留版本。残缺摘要不会覆盖已有完整正文，笔记和标签也不会被重新采集覆盖。
- 检索覆盖原文、作者、笔记、标签和关联研究结果，支持中文短词、字面标点、多词共同匹配和精确标签。SQLite 提供 FTS5 trigram 时启用索引；没有该模块时保留子串检索能力。
- 导出 JSON，或包含 `library.md`、`records.json` 与本地图片的 ZIP。原文快照、笔记、关系和模型研究分别保留。

导航前会检查实际可编辑框，发现未发送文字就停止导航，不覆盖草稿。占位提示不算草稿。平台验证、账号变化、断连、停止或运行中断会暂停接管；旧授权不会在服务重启后自行复活。

图片仅从 `pbs.twimg.com` 读取，不附带 Cookie。单图上限8MB、单轮合计24MB，最多同时下载2张，并有有界短期缓存。服务不可用时，手动读取结果可进入扩展小容量待同步区；恢复后需主动同步并核对账号，超过容量会明确拒绝，不把缓存称为已经落盘。

## X 书签

工作台的“X 书签”连接已有资料库，无需另建收藏系统。手动保存与 X 书签观察分别记录；按原帖 ID 去重，按账号区分书签来源。正文、图片、个人笔记、原始观察时间与来源证据保留，旧归档不会冒充本轮刷新，未再次出现的记录也不会被删除。

- 扩展侧栏的“读取并保存当前加载的书签”可以在手动模式打开全部书签页，保存已加载的帖子与可取得图片。
- 批量同步在工作台运行，需要当前版本扩展、绑定及主动开启接管。“检查新增书签”从顶部检查，到达连续历史重叠页或预算后结束；“继续读取历史书签”按账号保存最后已处理原帖 ID，下次先找回该位置。两种位置分别维护。
- 每页先持久化原文、候选和读取状态，正文和图片一致且可核对的已有资料直接复用；新增或变化条目按预算保存，不完整的条目随后进入详情补读。取消、中断或失败保留已存资料和候选，不自动重放。部分条目仍不完整时，可以“运行／补全本批次”。
- 每轮条数、后续翻页和总时间有上限。历史续读先定位旧位置，定位不消耗后续翻页预算，但计入总时间；若当前页面仍停在锚点附近，会直接继续，避免从头滚动。旧位置前的内容留给“检查新增”处理。页面停滞、找不到旧位置、空列表和预算用尽分别说明；滚动停滞**不能证明已取完全部历史**。旧位置因移动或删除而失效时，可勾选“从顶部重新扫描历史”，不会删除已有资料。当前入口读取全部书签列表，不支持把书签文件夹或推荐栏误当同一来源。
- “阅读本地书签”进入资料库的书签筛选，可搜索、记笔记、导出，或选择后创建模型研究。原帖和长帖中记录的资源链接可以直接打开，不自动抓取站外正文，也不自动调用模型。

已有 personal-ingestion 的规范 JSON 可显式导入：

```shell
python -X utf8 -B run_x.py import-bookmarks --posts-dir "/your/archive/x/posts" --attachments-dir "/your/attachments/x"
```

导入只读旧库，复制登记的允许图片并按内容去重；不移动、覆盖或删除旧文件，不接入旧模块的定时任务和凭据。导入的旧版本不会覆盖工作台已保存的当前版本或用户笔记。缺失观察时间显示为“未取得”，缺图与受限正文保留原始边界；CLI 输出逐项失败，不能用文件扫描数量冒充成功导入。HTTP/MCP 不开放任意本地路径导入。

扩展动作与后台同步已经过合成页面、真实桥接协议、预算截断、跨账号拒绝、旧位置缺失、重复导入和图片保全测试。本机还用已有真实归档验证过导入、阅读、图片、检索和导出；一次旧模块书签首屏读取也已验证，**不把该读取当成扩展的真实书签页验收**。扩展离线或绑定页未开启时，批量按钮保持不可运行，本地阅读继续可用。

## 研究与来源复用

输入研究问题、搜索词、精读和翻页上限、时间预算，然后选择来源方式：

- **先复用本地，缺额再在线采集**：按关键词复用正文完整、附件可核对的固定版本，再补足在线来源。保留旧资料原观察时间。
- **重新在线采集**：主动搜索、读取当前站内内容。
- **仅使用本地匹配资料**：不操作浏览器；没有合格来源时明确失败。

“预览本地匹配”显示作者、片段与原观察时间。匹配是字面检索，不是语义推荐；支持核对 `from:` 作者，本地无法完整核对的日期、`to:` 或过滤查询不会被当成已有精确匹配。明确勾选资料后直接研究所选资料，不追加在线搜索。

在线研究先保存候选 ID，再逐个定位并精读，减少页面往返。查询位置、已读／失败／待处理状态与固定来源版本随任务保存；用户点击“运行／继续任务”后接续未完成项，失败和重启不自动重放。多个在线研究串行使用绑定页，避免争抢位置。状态更新只传概况，详情按需读取，空闲或隐藏工作台时降低轮询频率。

内容执行器可以选择：

- **当前 AI 客户端／MCP**：收集后等待客户端读取任务包和实际图片，再接回符合 schema 的中文摘要、精确引文、翻译及疑点。也可在工作台粘贴结构化 JSON。
- **本机 Codex 订阅 CLI**：使用宿主已有 ChatGPT 登录，隔离用户配置并禁用工具执行。需要另行安装兼容 CLI；本项目尚未完成真实订阅生成验收，不读取或复制登录凭据，也不自动回退到 API Key。
- **显式配置的兼容 API**：配置含 `/v1` 的地址、模型和密钥环境变量名，用带有该变量的进程启动服务。仅在选择并运行任务时发送本轮资料和最多12张实际图片；可能计费，不自动切换提供商、跟随重定向或重试。真实付费提供商尚未验收，本地模拟接口有测试。

模型只能引用任务内固定版本；逐字引文必须匹配原文。翻译、摘要和判断不写回原文。帖子内容是不可信资料，不能授权模型修改设置、执行任意 JavaScript 或新增站内动作。

## MCP 与本机 HTTP

先在“连接与运行”生成本机 AI 凭据。凭据保存在项目 `data/api-token.txt`，轮换后旧凭据失效。客户端配置示例中，替换为你安装目录的绝对路径；工作台也会生成当前机器的命令。

```json
{"mcpServers":{"x-workbench":{"command":"python","args":["-X","utf8","-B","/absolute/path/to/x-twitter-workbench/run_x.py","mcp"]}}}
```

工具包括 `x_status`、`x_search`、`x_local_sources`、`x_get`、`x_annotate`、`x_browser`、`x_create_task`、`x_run`、`x_cancel`、`x_task`、`x_packet`、`x_complete`、`x_source_image`、`x_create_bookmark_sync`。`x_status` 返回概况，完整来源、结果和事件使用 `x_task`。图片 index 从0开始。

HTTP 入口为 `POST http://127.0.0.1:8915/api/v1`，使用 `Content-Type: application/json` 和 `Authorization: Bearer <本机凭据>`。例如：

```json
{"action":"search","args":{"query":"合成示例关键词"}}
```

书签同步使用 `create_bookmark_sync`，`mode` 为 `recent` 或 `backfill`，通过 `run` 启动；`search` 可传 `collection: "bookmarks"` 与可选 `owner` 筛选书签。直接浏览器动作新增 `bookmarks`，仍受同一接管许可约束。

研究的 `source_mode` 可为 `hybrid`、`online` 或 `local`。外部接口不能配对扩展、更改接管权限或模型设置，也不能发布站内互动。

## 数据与隐私

`data/` 保存 SQLite、图片、笔记、任务、凭据和必要诊断，均被 Git 忽略。源码、扩展包及自动化测试不附带真实账号、帖子、采集媒体、截图、数据库或私人验收资料。测试中的帖子、身份、文本、图片和凭据都是明确构造的合成夹具，不需要登录 X。

扩展只申请 X／Twitter、图片域名、本机8915，以及固定动作所需的 `activeTab/scripting/storage/sidePanel/alarms`；不申请所有网站、Cookie、历史或 debugger 权限。只有主动运行所选模型研究时，才把当轮资料发送给该模型执行器；手动保存不调用模型。

备份应覆盖自己的 `data/`，克隆 Git 不能恢复资料。数据库升级保留原文、笔记、版本和任务，并增加派生检索表；替换或恢复数据库前先停止服务，并保留后续新增资料。不要将 `data/`、浏览器登录态、模型密钥或私人日志打入源码包和问题反馈。

## 验证与真实边界

```shell
python -X utf8 -B -m unittest discover -s tests -p 'test_*.py' -v
node --test tests/test_extension.cjs
node --check x_workbench/static/app.js
node --check extension/background.js
python -X utf8 -B tests/benchmark_store.py --posts 10000
```

合成测试覆盖去重、版本与笔记保全、中文短词、索引升级、媒体及导出、失败后跨实例续跑、本地复用、在线补充、HTTP/MCP、模型协议、授权停止和账号漂移。基准脚本默认只测当前实现的内存合成资料；可显式传 `--baseline <公开标签或提交>` 比较历史，不依赖私有开发历史。数字不代表实网或模型吞吐。

开发阶段做过有限的真实登录页样本验证，包括长文、引用、同作者父帖／回复、图片、研究整理和停止后拒绝操作；这些私有样本与现场证据不随发布。以下边界仍然存在：

- X 当前页面结构可能变化；本地测试不保证所有账号、页面和未来版本兼容。
- 线程仅代表本轮取得的明确关系部分，不是完整会话、全部回复或完整账号归档。
- X Articles 只保留可识别链接，不声称已读文章全文；不下载视频。
- 侧栏关闭后的持续运行、账号切换、最小化／休眠、平台验证与长期稳定性仍需独立实测。浏览器关闭或电脑休眠时不能继续浏览。
- 真实 Codex CLI 与付费 API 生成尚未验收。
- 当前只开放阅读、记录与研究；没有发帖、回复、点赞或私信执行入口。
